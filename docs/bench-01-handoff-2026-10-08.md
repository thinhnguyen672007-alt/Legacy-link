- Chip MAC: `cc:db:a7:60:3c:64`; ESP32-D0WD-V3 revision 3.0, 4 MB flash.

- Source: physical OpenModSim RTU connection through CH340 USB–TTL. Readings were

## Fixture and observed readings

[Profile A](../firmware/legacy-link-core/examples/bench-demo-a.json) matches the
map physically read in this run. Simulator address 0 returned exception `0x02`;
addresses 1–3 succeeded. Do not change these to 0–2 by assuming the GUI label is
one-based: the addresses below are the actual protocol addresses sent on the wire.

| Metric | Protocol address | Conventional reference | FC | Type | Raw word / decoded value | Scale | Expected converted value |
| --- | --- | --- | --- | --- | --- | --- | --- |
| temperature | 1 | 40002 | 3 | INT16 | 250 / 250 | 0.1 | 25 C |
| current | 2 | 40003 | 3 | UINT16 | 144 / 144 | 0.01 | 1.44 A |
| rpm | 3 | 40004 | 3 | UINT16 | 1272 / 1272 | 1 | 1272 rpm |

Profile A sampling interval is 2000 ms. Actual serialized values included
`25.00000037`, `1.439999968`, and `1272`; small decimal differences are float scaling.
Scale is applied once by firmware. Backend/frontend must not multiply again.

[Profile B](../firmware/legacy-link-core/examples/bench-demo-b.json) is prepared,
not physically accepted in this run: same `BENCH-01`, temperature address 49
(40050), FC03/INT16/scale 0.1, sampling 1000 ms, unchanged current/rpm map.
It requires a simulator holding register at protocol address 49 with raw 420 for
expected 42 C. Switching A/B is sequential on the same gateway, not simultaneous
reading of two PLCs. No firmware reflash is needed for runtime profile switching.

Signed-value check still to repeat through this DB path: at temperature address 1,
raw word `65356` (hex `FF4C`) decodes as INT16 `-180`; scale 0.1 gives approximately
`-18 C`. Negative decoding was established in the earlier
[physical report](../firmware/legacy-link-core/docs/hardware-validation-2026-10-08.md),
but this run did not repeat the negative value through PostgreSQL.

Demo-only alarm settings in both fixtures: `OVERHEAT`, high at 90 C, critical at
100 C, hysteresis 3 C. These are illustrative thresholds, not approved machine limits.

## Contract and integration decisions

Existing telemetry/status/alarm topic and payload semantics stay unchanged:
`schemaVersion: 1`, matching device/topic ID and epoch milliseconds. Configuration
published to MQTT is flat JSON with `requestId` and `registerMap`; HTTP's `{config}`
request wrapper is removed by the backend before MQTT publication.

ACK keeps `requestId`, `result`, `reason` and `persisted`. A client must explicitly
report `persisted: false` as applied in RAM but not saved. Host/backend tests cover
this failure state; no physical flash fault was induced in this run. LWT timestamp
remains the time of CONNECT, not the time power was lost.

PR #51's separate `devices/{deviceId}/diagnostics` topic and gateway state/probe
extensions need coordination with Huy before using them in the team's deployed
consumer/UI. They do not add unagreed fields to telemetry/status/alarm. Success
count can be derived from `readings.filter(r => r.success).length`; latest read
failure comes from each reading's `errorCode` and `sampledAt`. No new counter field
is necessary. The team's UI should distinguish gateway contact from measurement
freshness and show failed/stale reads rather than an old number as current data.

Use one control HTTP process for this demo. Commissioning serializes operations per
gateway within that process. The existing catalog-publish API and other manual
publishers must not be used concurrently; a shared lock across those publishing
paths remains an integration item for the backend owner.
